## 2. 创建容器（标准步骤）

1. 入口：平台 →「我的任务（GPU）」→ 新建容器。
2. 规格：
   - GPU：**A100 / 1 GPU**（不要选双卡：实测双卡容器每次只有一张能建 CUDA 上下文）。
   - 镜像：**标准版 PyTorch (CUDA) Full V1.5.0**（不要选带"测试/浦源"的镜像）。
   - CPU/内存：4 vCPU / 40 GiB。
   - 磁盘：**挂载现有磁盘**（例如 4607），不要新建，否则看不到之前上传的数据。
   - 名称：`rsg-YYYYMMDD-<用途>`，例如 `rsg-1122-baseline`。
3. 建立后状态变为"运行中"，点 `Terminal` 进入。

**【实测】镜像里的 base torch 是 1.8.1+cu111**，不要直接拿来训现代模型；所有依赖装进自己的环境。

## 5. 环境构建（一次性，约 20–40 分钟）

### 5.1 为什么不用 conda

**【实测】** conda 4.10.1 的经典 solver 极慢，且**不支持 `--solver=libmamba`**；官方 `conda.anaconda.org` 在本平台**不可达**。改用 micromamba。

### 5.2 安装 micromamba（约 7MB）

```bash
mkdir -p ~/bin ~/rsg_work/tmp
curl -L --fail --retry 3 --connect-timeout 15 --max-time 180 \
  https://micro.mamba.pm/api/micromamba/linux-64/latest \
  -o ~/rsg_work/tmp/micromamba.tar.bz2
tar -xjf ~/rsg_work/tmp/micromamba.tar.bz2 -C ~/rsg_work/tmp
cp ~/rsg_work/tmp/bin/micromamba ~/bin/micromamba
chmod +x ~/bin/micromamba
~/bin/micromamba --version     # 【实测】2.8.1
```

### 5.3 创建环境并装 PyTorch（A100 用 cu121）

> 平台驱动 535 → 最高 CUDA 12.2，**不要装 cu124/cu128 轮子**。

```bash
export MAMBA_ROOT_PREFIX=/home/jovyan/conda
~/bin/micromamba create -y -p ~/conda/envs/rsg python=3.10 pip
```

**实测可用的镜像**（四个 URL 均返回 200）：

| channel | 镜像 |
|---|---|
| pytorch | `https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/pytorch` |
| nvidia | `https://mirrors.sustech.edu.cn/anaconda-extra/cloud/nvidia` |
| defaults | `https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main` |
| r | `https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/r` |

推荐用 conda 渠道装 torch（与既有项目一致）：

```bash
nohup env MAMBA_ROOT_PREFIX=/home/jovyan/conda MAMBA_DOWNLOAD_THREADS=1 \
  ~/bin/micromamba install -y -p ~/conda/envs/rsg \
  --override-channels \
  -c https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/pytorch \
  -c https://mirrors.sustech.edu.cn/anaconda-extra/cloud/nvidia \
  -c https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main \
  -c https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/r \
  pytorch=2.3.1 torchvision=0.18.1 pytorch-cuda=12.1 \
  > ~/rsg_work/logs/torch_install.log 2>&1 &

echo $! | tee ~/rsg_work/logs/torch_install.pid
tail -f ~/rsg_work/logs/torch_install.log
```

**【实测】** 清华镜像并发下载大包会失败；`MAMBA_DOWNLOAD_THREADS=1` + 南科大 nvidia 渠道是可行组合。看到 `Transaction finished` 才算成功。

> 备选【建议，待验证】：`pip install torch==2.3.1 torchvision==0.18.1 --index-url https://mirrors.tuna.tsinghua.edu.cn/pytorch-wheels/cu121`。若 pypi 官方源超时（实测 781MB 轮子会超时），优先走 conda 镜像。

## 6. 网络现实与绕行（最重要的一节）

| 目标 | 实测状态 | 绕行 |
|---|---|---|
| `conda.anaconda.org` | **不可达** | 清华/南科大镜像（见 §5.3） |
| PyPI 大包（torch 781MB） | **超时** | 走 conda 镜像；或 TUNA 的 pytorch-wheels；或本地上传 |
| GitHub（git/curl） | **DNS 对 libcurl/git 失效**：`getent` 偶尔能解析，但 `git`/`curl` 报 `Could not resolve host`；Git 2.25.1 不支持 `http.curloptResolve`；无 `/etc/hosts` 写权限；`LD_PRELOAD` 劫持 `getaddrinfo` 失败；本地 CONNECT 代理直连固定 IP 超时 | ① 优先用**平台文件管理器上传**代码/权重；② 必须走 GitHub 时用 `curl --resolve`（见下）；③ 用 `https://codeload.github.com/.../tar.gz` 同理 |
| Hugging Face | 未系统测试；不要依赖 | 本地下载 → 上传到 `~/rsg_work/weights/`；代码里 `local_files_only=True` |

### 6.1 可用的 GitHub 绕行（实测成功）

```bash
# 1) 先拿到当前可用的 IP
getent ahostsv4 github.com | head -n 1

# 2) 用 --resolve 固定解析，TLS 校验仍然有效
curl -fsSL --resolve github.com:443:20.205.243.166 \
  --connect-timeout 5 --max-time 60 \
  "https://github.com/<owner>/<repo>/archive/refs/heads/main.tar.gz" \
  -o repo.tar.gz

# 3) 校验（本地算好 sha256 带过来）
sha256sum repo.tar.gz
```

> 固定 IP 会变，每次先 `getent`；不要在脚本里硬编码旧 IP。

### 6.2 代码同步的优先级

1. **本地打包上传**（最稳）：本地 `tar -czf code.tar.gz` → 平台文件管理器 → 解压。
2. `curl --resolve` 下载 release tarball / patch。
3. `git clone/pull`（最不稳，DNS 故障时放弃）。

## 7. 长任务与断线

**【实测】** 网页 Terminal 断线**不会**杀掉 `nohup` 启动的进程；`tail -f` 里按 `Ctrl+C` 只退出日志查看。

标准写法：

```bash
cd ~/rsg_work/code

nohup env PYTHONUNBUFFERED=1 python -u train_yolo.py \
  --data ~/rsg_work/data/rs_grounding_train_v1 \
  --imgsz 1024 --epochs 40 --batch 8 \
  > ~/rsg_work/logs/yolo_$(date +%Y%m%d_%H%M%S).log 2>&1 &

echo $! | tee ~/rsg_work/logs/yolo.pid
tail -f ~/rsg_work/logs/yolo_*.log
```

断线重连后：

```bash
PID=$(cat ~/rsg_work/logs/yolo.pid)
ps -p "$PID" -o pid,etime,%cpu,%mem,stat,cmd
tail -n 60 ~/rsg_work/logs/yolo_*.log
nvidia-smi --query-compute-apps=pid,used_memory --format=csv,noheader
```

**不要**重复启动同一个训练（会争 GPU/显存）；先 `ps` 再决定。

## 8. 文件传输与校验

- **上传**：JupyterLab 左侧文件区 → 进入目标目录 → 上传。`GPU磁盘管理 → 文件管理` 在**不开容器**时也能上传到持久盘（实测）。
- **下载**：文件区右键下载；大文件先打包。
- **校验（必须）**：

```bash
# 平台侧
sha256sum result.tar.gz | tee result.tar.gz.sha256

# 本地（PowerShell）
$expected = (Get-Content result.tar.gz.sha256).Split()[0].ToLower()
$actual = (Get-FileHash result.tar.gz -Algorithm SHA256).Hash.ToLower()
if ($actual -ne $expected) { throw "SHA256 mismatch" }
```

- 结果包建议结构：`config.json` + `metrics.json` + `weights/` + `logs/` + `SHA256SUMS`。

## 11. 已知坑清单

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | 双卡容器只有一张卡能建 CUDA 上下文（两张卡轮流失败） | 平台双卡分配不稳定 | **只用单卡**；不要反复抽双卡 |
| 2 | `conda install --solver=libmamba` 报 `unrecognized arguments` | conda 4.10.1 太旧 | 用 micromamba |
| 3 | `conda.anaconda.org` 连接失败 | 平台出网限制 | 清华/南科大镜像 |
| 4 | 大包下载到一半失败 | 并发连接过多 | `MAMBA_DOWNLOAD_THREADS=1` |
| 5 | `pip install torch` 超时 | PyPI 大文件 | 走 conda 镜像 / TUNA wheels / 本地上传 |
| 6 | `git`/`curl` 报 `Could not resolve host: github.com` | 容器 DNS 对 libcurl 失效 | `curl --resolve` 或文件上传 |
| 7 | `libX11.so.6` / `libnvf.plugin.so` 报错 | headless 缺 X11 插件 | **忽略**，不影响计算 |
| 8 | 长时间 `pip/conda` 安装后 `import torch` 失败 | 安装事务未完成/进程被杀 | 先 `pgrep -af 'conda|pip'`，确认结束再验证 |
| 9 | 网页断线后终端回到 `(base)` | 新 shell | `conda activate ~/conda/envs/rsg`；后台任务仍在 |
| 10 | `torch 1.8.1` 在大 batch 上 `device-side assert`（randperm 越界） | 旧版 torch 在 A100 的已知问题 | 不要用 base 环境；必要时在 CPU 上生成索引 |
| 11 | 中文粘贴变成 `**version**` 之类 | 终端/输入法转义 | 用 heredoc 或上传脚本文件 |
| 12 | `LD_LIBRARY_PATH` 污染系统 `curl/git` | conda 库覆盖 | 调网络命令时 `env -u LD_LIBRARY_PATH` |
| 13 | 容器内无 `/etc/hosts` 写权限 | 平台限制 | 不要试图改 hosts |
| 14 | 平台 Docker-in-Docker 未验证 | 未知 | **不要假设容器里能 docker build**；镜像在本地/云端构建 |
| 15 | 持久盘大小未知 | 未查 | 开机 `df -h ~`；大权重及时清理 |

## 14. 与本地环境的差异（容易踩）

| 项 | 本地 WSL | 自强5000 A100 |
|---|---|---|
| GPU | RTX 5070 Ti Laptop **12GB**，compute cap **12.0 (sm_120)** | A100-PCIE-**40GB**，sm_80 |
| 驱动 | 617.42 | 535.129.03 |
| 可用 CUDA | cu128 轮子（torch 2.7+） | **cu121**（不要 cu124/cu128） |
| 用途 | 快速迭代、YOLO/CLIP 小实验、可视化 | 全量训练、批量推理、最终权重 |
| 环境 | 新建 `rsg-local`（torch cu128） | `~/conda/envs/rsg`（torch cu121） |

**代码必须与版本无关**：不要用只有 torch 2.7+ 才有的 API；训练脚本里写 `--device auto`，推理脚本同样。
