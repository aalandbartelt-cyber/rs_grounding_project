# 独立模型路线：遥感中文检索与定位

调研日期：2026-11-21。状态：研究方案，尚无候选模型在本项目上的训练成绩。本文只新增到 Z 分支工作目录，不修改原方案、模型、训练数据或冻结评测。

## 1. 决策与依据

建议将“预训练微调、模块组合、知识蒸馏”安排成连续的实验阶段。这三件事解决不同问题，可以结合：先得到可靠的微调系统，再只对实际薄弱环节引入教师监督。

首轮主线：D-FINE-S 四类检测器 + 中文图文模型对照筛选 + 保留全图坐标的区域匹配。RS-M-CLIP 与 SigLIP 2 Base 是新候选，Chinese-CLIP 是可比较的已有基线。模型胜负由本地冻结评测决定。

第二轮：参考 RT-DETRv4，验证视觉基础模型特征蒸馏；语义选框仍不足时，再验证多模态教师的区域排序蒸馏。蒸馏训练后只部署学生侧组件。

更高成本的端到端视觉语言定位模型作为挑战者。完整复现大型视觉搜索、强化后训练不作为当前首个实验。

这是一条根据本项目数据设计的假设路线，不是已有论文已验证的完整架构，也不构成“首次提出”或性能领先的声明。

## 2. 本项目约束

依据 z_evaluation/REPORT.md、audit/build_summary.json、splits/manifest.json 和官方训练包 README：

- 当前固定训练划分是 346 张图、1913 个目标；dev 为 30 张图、612 个目标；另外 51 张原验证图作为补充检查。
- 原训练包车辆目标只分布在 7 张训练图中，原 val 没有车辆。目标数不能当作独立场景数。
- dev 有 458 个车辆目标，占 612 个目标约 74.84%，但车辆场景只有 3 张。总分提升须同时检查各类别与每张图表现。
- 描述是中文，且存在跨图同文本、同图同文本多目标。不能依靠 query_id、标注顺序或预存答案解决歧义。
- 任务需要两个输出：文本检索图像，以及给定图像中的文本对应框。定位部分合计占主分 70%，检索占 30%。
- 定位指标是 Acc@0.5 与 Acc@0.75，不等同于 COCO mAP。候选框定位正确之后，还必须选中描述对应的实例。
- 本次 nvidia-smi 实测本机为 NVIDIA GeForce RTX 4060 Laptop GPU、8188 MiB。8GB 是实验规划依据；实际 batch、分辨率和训练显存需运行测量。
- 评测要求离线运行，最终包体积与推理时间需实测。资料中的包体积上限存在不同版本，应以平台最新规范为准；训练教师不必放入部署包。

上述公开数据集成绩不代表本赛题成绩，不跨数据集、不同训练预算和语言设置直接排“最好模型”。

## 4. 我们自己的可检验方案

### 4.1 首轮系统

1. 对整图和重叠切片生成候选框，映射回原始图坐标并去重。整图通道保留大目标与全局信息，切片通道用于小目标。
2. 对每个候选保留紧框裁剪、适度扩展上下文、全图表示及归一化坐标。紧框负责外观，上下文负责周围环境，坐标保留“左边、上方、中央”等线索。
3. 中文图文编码器输出文本表示与区域表示。先用简单匹配基线，再加入坐标特征的小型排序头。
4. 只有错例证明邻近关系是主要瓶颈时，才加入少层关系 Transformer，让文本与多个候选、位置及邻近关系交互。单个候选的绝对坐标不足以表达“某目标旁边”。
5. 定位按融合得分输出一个框；检索结合全图相似度与目标区域匹配得分，对图像排名。不同模型分数需要在 dev 上校准，不能任意相加。
6. 同一评测图像的候选框和区域特征预先缓存，多个查询复用。缓存只能来自输入图像，不得读评测真值。

候选模型本身已经含有 CNN 与 Transformer 等不同结构。是否增加新模块，应由它解决的错误类型和消融结果决定。

### 4.2 训练策略

- 从公开预训练权重迁移，先冻结大部分骨干，训练检测/排序头；再比较低学习率部分解冻或适用的适配器。LoRA 是否更好必须实测，不一律强加给所有模块。
- 图文训练使用标注的目标裁剪与适量上下文，同时保留全图监督，避免把整张复杂图当作描述中的唯一目标。
- 同图其他同类实例可作为困难候选，但同文本对应的多个合理目标不能无条件当成错误负样本。构建多正样本或歧义屏蔽规则，保留原始主评测口径。
- 按原始图像/场景采样并关注类别平衡，避免密集车辆图以目标数量支配训练。
- 几何增强必须同步转换框与位置描述；含“左、右、上、下”的文本不能配合未经更新的翻转/旋转。颜色增强也要考虑颜色属性描述。
- 初始切片尺度、重叠、最大候选数和 batch 均是待测参数。密集图需检查候选数上限和截断，避免默认 top-K 漏掉大量车辆。

### 4.3 大模型如何帮助小模型

蒸馏是额外的训练监督，不是模型文件压缩，也不保证学生保持老师全部能力。量化则主要改变数值精度，不能替代训练上的蒸馏。

可依错误来源选择：

| 薄弱环节 | 教师 | 学生学习内容 | 检查条件 |
|---|---|---|---|
| 候选漏检、特征泛化弱 | DINOv3 等冻结视觉基础模型；或验证更强的检测教师 | 对齐后的视觉特征，或可靠的框/类别分布 | 先测候选覆盖率；特征蒸馏仍保留真实框监督 |
| 同类多个候选选错 | 本地可运行、经中文遥感验证的多模态教师 | 候选相关性软分布、目标属性、相对位置关系 | 先验证教师在该类错例上确实优于学生；不能只信教师自报置信度 |
| 教师系统有效但推理太重 | 第一阶段验证有效的组合系统 | 检索分布与选框排序，必要时分步迁移 | 单独核算训练成本和最终部署成本 |

概念上的目标为 L = L真实检测 + L图文匹配 + L候选排序 + λ L蒸馏。各项不能直接用未经校准的固定权重相加；先分阶段训练，逐项验证。

跨架构特征需要空间与通道对齐；框集合监督需要匹配；区域排序蒸馏需要老师与学生对应相同候选。多教师相互冲突时不能简单平均。

教师只处理冻结训练划分及规则允许的外部训练数据。不得用 dev/val 真值生成训练样本。允许的外部遥感数据也需排查与留出评测图像重复或重叠。

仅在 346 张训练图上重复教师输出不会自动创造新的视觉多样性。保留真实标注监督，对错误伪标签做过滤；有用的额外公开数据和匹配的任务知识可能比盲目增大教师更有价值。

## 5. 实验顺序与停止条件

| 编号 | 实验 | 主要回答的问题 |
|---|---|---|
| E0 | 用来源可追溯的已有 Chinese-CLIP / Grounding-DINO 建立真实模型参考；输出统一 pred.json | 当前真实能力与错误类型是什么？现有打分自检不算模型成绩 |
| E1 | D-FINE-S 迁移到四类；固定候选预算，对比整图与整图+切片 | 候选覆盖率和框精度是否是主要瓶颈？ |
| E2 | 固定候选，对比 Chinese-CLIP、RS-M-CLIP、SigLIP 2；先零样本/冻结头，再对入选者同预算微调 | 中文与遥感预训练谁更适合本数据？ |
| E3 | 最佳基线依次加入上下文、坐标、关系融合；每次只改变一个因素 | 组合模块是否真的改善实例选择？ |
| E4 | 在同一学生结构、相同数据与可比较训练预算下加入特征蒸馏 | 训练教师的额外成本换来了多少泛化收益？ |
| E5 | 仅在语义关系错例仍明显时尝试多模态排序蒸馏；并与直接增加学生训练预算对照 | 大语言教师是否比更简单的办法有效？ |
| E6 | 将胜出的组合方案与一个可复现的端到端 grounding 模型比较，再测完整离线流程 | 是否值得换主线；部署约束是否满足？ |

E0 若使用仓库已有权重，必须先确认权重是否已用留出图像训练过；来源不明则改用可追溯的原始公开权重。已有清单的 Chinese-CLIP 权重 hash 与 source hash 不同，并不能据此确定其训练经历。

固定记录：四个主指标、官方权重总分、每类别/每图表现、候选覆盖率@0.5/@0.75、选择正确率、训练与推理显存、完整运行时间、最终部署体积、种子、权重来源及训练数据清单。

候选覆盖率定义：每个查询的真值框是否存在至少一个候选达到指定 IoU。它是读取真值的离线诊断上限，不允许用真值替模型选框。

主要选择在 dev 上进行，51 张原 val 保留作阶段检查，避免反复调参把两套留出都用成训练反馈。最终候选检查多个种子；当前 dev 只有 3 个车辆场景，区间估计不能补足独立场景不足。

候选覆盖不足时优先改分辨率、切片与候选数；覆盖充分而选错时优先改中文、属性与关系融合；学生没有稳定收益时停止堆叠教师。检测框几何精度、文本对应实例选择、检索排序三者分开诊断。
