## 2. 数据纪律

### 2.1 split 只读

- `official_train`（376）只训练；`official_val`（51）只报告；`dev4`/`dev_vehicle` 用于选模。
- **val 不进训练、不进增强、不参与早停**。一旦发现，整轮实验作废。
- 每次 split 变更：PR + 重算 SHA256 + 通知全员。

### 2.2 标签解析（实测坑）

- `shapes[].points` 是 **4 个角点**，不是两角点：

```python
def bbox_xyxy(shape):
    xs = [p[0] for p in shape["points"]]
    ys = [p[1] for p in shape["points"]]
    return min(xs), min(ys), max(xs), max(ys)
```

- 用 `min/max` 后必须断言 `x2 > x1 and y2 > y1`；本项目 2716 个框全部合法，若出现非法框说明解析错了。
- 坐标是**原图 1024 尺度整数**；切片/缩放的坐标要映射回原图再算 IoU。
- XML 与 JSON 框数一致（2716 = 2716）；XML 没有 `description`，**训练文本只能用 JSON**。

### 2.3 切片

- 切片重叠 15–20%；边缘目标至少完整出现在一个切片里。
- 切片坐标映射：`x_orig = x_tile + offset_x`；缩放时 `x_orig = x_tile / scale`。
- 合并用类内 WBF 或 NMS；**先映射回原图再加权**，不要在切片坐标系里合并。
- 空切片（无目标）不要当负样本训练检测器（YOLO 会自动处理背景，但全空图会浪费）。

### 2.4 类别映射（统一，禁止各自定义）

| 名称 | 训练 class_id | 提交 category_id |
|---|---:|---:|
| 油罐 | 0 | 1 |
| 舰船 | 1 | 2 |
| 车辆 | 2 | 3 |
| 飞机 | 3 | 4 |

任何转换函数只允许存在一份（`src/common/labels.py`），并带单测。

## 3. 评测口径

### 3.1 本地评分器必须与官方公式一致

```
total = 0.1*R@1 + 0.2*R@5 + 0.6*Acc@0.5 + 0.1*Acc@0.75
```

- `R@1/R@5`：来源图排第 1 / 出现在前 5 任意位置；第 2–5 名不比顺序。
- `Acc@0.5/0.75`：预测框与 GT 框 IoU ≥ 阈值；完全重合=1，刚好接触=0。
- **分母分开统计**：检索查询数与定位查询数不同，不能合并成一个准确率。
- 用 PDF 算例自检：`R@1=0.30, R@5=0.60, Acc@0.5=0.624, Acc@0.75=0.389 → 0.5633`。评分器必须复现到小数点后 4 位。

### 3.2 歧义要报两个口径

图内存在 849 个"同描述多框"。本地评测必须同时报：

| 口径 | 定义 | 用途 |
|---|---|---|
| `strict` | 预测框与**该条标注框**算 IoU | 最保守，模拟"每条查询有唯一 GT" |
| `any-dup` | 预测框与**同图同描述的任一卷标框**取最大 IoU | 乐观上限，衡量"选没选到正确组" |

**只报 any-dup 会自欺**；只报 strict 会把结构歧义算成模型错误。两个都报，并在报告里解释差距。

### 3.3 噪声与显著性

- val 定位 191 个框：1 个框 = 0.52 个点；**差异 <2 个点不要当真**。
- 所有主指标给 **bootstrap 95% CI**（对 query 重采样 1000 次）。
- 模型选择用 dev4（含车辆）；val 只做最终报告。两者差距 >10 点要查分布/解析/格式。

### 3.4 空候选与异常

- 无候选：该 query 记 Acc=0（不进分母之外的特殊处理）；但 `pred.json` 必须仍输出合法框。
- 预测框越界：按平台要求裁剪到 `[0, W]×[0, H]`，再算 IoU（本地评测用同一规则）。
- `score` 用模型置信度（0–1）；没有置信度时用 1.0，不要写 NaN/Inf（JSON 不支持）。

## 4. 训练注意事项

### 4.1 小目标（本项目第一优先级）

- 车辆中位短边 **16px**、13.7% 的框 <16px。1024 整图训练必然吃亏。
- 必做对照：`imgsz=1024` vs `1536` vs `2×2 切片`。不要凭感觉选。
- YOLO 的 `mosaic` 会把小目标缩得更小：建议 `mosaic=0.3~0.5`，最后 10 epoch `close_mosaic=10`。
- 拥挤车辆图（单图 146–168 个目标）：`max_det=500`，NMS IoU 0.6–0.7，避免互相压制。
- 不要用随机旋转 90° 做增强（框要跟着变换，且方位词语义会变）；检测器可用水平/垂直翻转，但**重排器训练不要翻转**（描述含"左/右"）。

### 4.2 类别不平衡

- 车辆：1022 框 / 7 图；飞机：936 框 / 258 图。**图像级**极不平衡，**框级**反而车辆最多。
- 不要简单过采样车辆图（只有 7 个场景，会过拟合）；用光度增强 + 切片 + DIOR 预训练提升泛化。
- 报告必须分类别给指标；总体 Acc 会被飞机主导。

### 4.3 文本与重排

- 描述 p50 约 50 字；Chinese-CLIP HF 版 `max_position_embeddings=512`，不会截断；但不要输入整段标注 JSON。
- 解析器至少抽：类别、颜色、尺寸（大/中/小）、方位（左/右/上/下/中）、状态（停泊/停放/行驶）。**方位词覆盖率 99.9%**，必须用几何特征承接，不能只靠文本向量。
- 颜色对飞机几乎无区分度（94% 白色）；不要指望颜色救飞机。
- 图内同文组：训练时把同文框都当正样本（或组内 soft label），**不要把同文框当负样本**，否则模型学不到东西。
- 硬负样本 = 同图、同类、不同描述；这是重排器的主要学习信号。
- 训练/验证按"图"划分，不能按"框"随机划分（同图框会泄漏）。

### 4.4 过拟合与早停

- 只有 427 张图；任何模型都要早停 + 权重衰减 + 强增强。
- 选模看 dev4 的总分，不只看 loss。
- 不要用 val 调任何超参；调参一律 dev4。

### 4.5 预训练

- YOLO：COCO 权重起步；若用 DIOR 预训练，类别映射到 4 类（DIOR 的 vehicle/ship/airplane/oiltank 子集），并在报告写明。
- Chinese-CLIP：官方权重 + 轻量适配层（LoRA/线性），不要全参微调（2525 样本会毁掉预训练能力）。
- GroundingDINO：只做零样本对照；如需微调，注意其英文文本塔与中文不兼容，代价高、收益不确定。

## 5. 推理与交付

### 5.1 离线加载（必须）

```python
import os
os.environ["HF_HUB_OFFLINE"] = "1"
os.environ["TRANSFORMERS_OFFLINE"] = "1"

from transformers import AutoProcessor, AutoModel
model = AutoModel.from_pretrained(
    "/workspace/weights/chinese-clip-vit-base-patch16",
    local_files_only=True,
)
```

- 权重用**绝对路径**（镜像内 `/workspace/weights/...`），不要依赖 `~/.cache/huggingface`。
- 不要调用 `hf download`、不要 `trust_remote_code=True`（除非代码已打包）。
- 启动时先做一次 `import` 与加载自检；失败直接走兜底，不要卡死。

### 5.2 体积（先确认 2GB / 10GB）

| 组件 | fp32 | fp16 | int8 |
|---|---:|---:|---:|
| Chinese-CLIP ViT-B/16 | ~750MB | ~380MB | ~190MB |
| YOLO11m | ~40MB | ~20MB | ~10MB |
| GroundingDINO-T | ~690MB | ~350MB | — |
| torch cu121（安装后） | ~2.4GB | — | — |
| onnxruntime（CPU） | ~50MB | — | — |

- 10GB：随便装；仍建议 ≤5GB，构建/上传更快。
- 2GB：**必须**去 torch → ONNX Runtime CPU；或只保留 YOLO+轻量文本匹配。P0 就要决策。

### 5.3 时间预算（60 分钟）

| 阶段 | GPU(A100) | CPU(兜底) |
|---|---:|---:|
| 模型加载 | 5–10s | 5–10s |
| 81 图检测（含切片） | 10–30s | 3–8min |
| 图库/切片 CLIP 编码 | 2–5s | 1–2min |
| 重排（~187 query × 20 候选） | 5–15s | 2–4min |
| 写盘/校验 | <1s | <1s |
| **合计** | **<2min** | **<15min** |

- 目标 GPU <10 分钟（同分按用时决胜）；留 5× 余量。
- 时间守卫：`elapsed > 45min` 时切快速路径（跳过重排，检测 top-1；检索用预计算向量）。
- 每张图只检测一次、只编码一次；跨 query 复用候选与特征。

### 5.4 `shm` 与多进程

- 评测容器常见 `--shm-size 2g`（本地复现命令里用到；平台实际限制待确认）。
- `DataLoader(num_workers=0)`；不要用多进程读 1024 大图。
- 用 `torch.inference_mode()` + `autocast`；不要保留计算图。

### 5.5 兜底（必须实现并测过）

| 异常 | 行为 |
|---|---|
| 图像缺失/损坏 | 该类别的默认框（中心 + 训练中位尺寸），score=0 |
| 文本为空 | 用最大候选；无候选用默认框 |
| 模型加载失败 | 纯启发式：检测器不可用→默认框；检索→按 image_id 排序 |
| 超时 | 快速路径，保证 60 分钟内写盘 |
| 单条 query 异常 | try/except 包住，写兜底，不中断整体 |

`run.py` 的骨架必须是"先保证写出合法 pred.json，再追求精度"。

### 5.6 `pred.json` 转换

```python
x, y = x1, y1
w, h = x2 - x1, y2 - y1
assert w > 0 and h > 0
bbox = [float(x), float(y), float(w), float(h)]
```

- `category_id` 是 1–4（不是 0–3）。
- `image_id` 统一转字符串（输入可能是 int）。
- `ranking` 去重、降序、至少 5 个；给全 81 个更稳（若平台允许）。

## 8. 常见错误速查

| 症状 | 根因 | 修复 |
|---|---|---|
| `w/h` 为负 | 两点顺序反了 / 只取了两点 | 用 `min/max` 遍历全部点 |
| Acc 异常低但检测看起来对 | `xyxy` 当 `xywh` 提交 | 统一在 `labels.py` 转换并单测 |
| 所有 grounding 都是同一类 | `category_id` 用了 0–3 | 映射到 1–4 |
| 检索结果对不上 image_id | int/str 混用 | 全部 `str()` 归一 |
| `ranking` 被判非法 | 重复/少于 5 个 | validator 先跑 |
| 断网后卡住 | `from_pretrained` 尝试联网 | `local_files_only=True` + 环境变量 |
| `torch` 装了 CUDA 12.8 在 A100 报错 | 驱动 535 不支持 | A100 用 cu121 |
| 本地 5070 Ti 报 `no kernel image` | torch 不含 sm_120 | 本地用 cu128 轮子（torch 2.7+） |
| `ultralytics` 把 torch 降级/重装 | pip 依赖解析 | `--no-deps` + 手动补依赖 |
| numpy 2 与 torch 2.3 冲突 | ABI | `numpy<2` |
| 本地评分比线上高 10+ 点 | 数据/格式/口径不一致 | 查 split、坐标、类别、strict/any-dup |
| Docker 构建巨慢 | 每次重装 CUDA 轮子 | 分层缓存；torch 层单独 COPY |
