> 依据：`docs/01_赛题审核与比赛思路.md`

## 2. 共享契约（先定接口，再写代码）

### 2.1 数据 split（Z 产出，所有人只读）

```
data/splits/
├── official_train.json    # 376 图，只用于训练
├── official_val.json      # 51 图，只用于报告（无车辆！）
├── dev4.json              # 从 train 分层抽取，含 4 类，用于选模
├── dev_vehicle.json       # 从 train 抽 1–2 张车辆图，专项调参
└── SHA256SUMS
```

- 每条 split 记录 `images: [image_id]`、`seed`、生成脚本的 git sha。
- **纪律**：`official_val` 不进训练；`dev4` 与训练集按图互斥；任何 split 变更必须提交 PR 并重算哈希。
- `dev4` 建议：飞机/舰船/油罐各 8–12 图，车辆 2 图（车辆总共只有 7 图，抽 2 张后剩 5 张训练，需在报告注明）。

### 2.2 候选框（M 产出，S/Z 只读）

`work/candidates/{image_id}.json`

```json
{
  "image_id": "1001",
  "width": 1024, "height": 1024,
  "model": "yolo11m@1024+tile2x2",
  "candidates": [
    {"cand_id": 0, "category_id": 2, "score": 0.91, "bbox_xyxy": [989, 487, 1009, 534]}
  ]
}
```

- 内部统一 **xyxy 原图坐标**；只在写 `pred.json` 时转 `[x, y, w, h]`。
- 每图每类默认 ≤20 个候选，车辆拥挤图 ≤50。
- `model` 字段用于追溯；同一实验目录下候选不可覆盖。

### 2.3 重排分数（S 产出）

`work/rerank/{split}/{query_id}.json`

```json
{
  "query_id": "g_0001",
  "image_id": "1001",
  "scores": [{"cand_id": 0, "text_sim": 0.31, "final": 0.72}],
  "model": "chinese-clip-b16+adapter-r16",
  "version": "2026-11-25"
}
```

- `final` 已含属性/几何融合；M 可直接 argmax，也可再加检测分做二次融合（需在实验记录中写明权重）。

### 2.4 提交产物（Z 产出）

`pred.json`：每条 query 一条记录，字段严格按赛题：

```json
[
  {"query_id": "r_0001", "type": "retrieval", "ranking": ["1001", "1002", "..."]},
  {"query_id": "g_0001", "type": "grounding", "image_id": "1001",
   "category_id": 2, "score": 0.91, "bbox": [989.0, 487.0, 20.0, 47.0]}
]
```

**硬性检查**（Z 的 validator）：
- `query_id` 全覆盖、无重复、无多余；
- `ranking` 降序、去重、≥5；
- `bbox` 的 `w/h > 0`、不越界（或按平台要求裁剪）；
- `category_id ∈ {1,2,3,4}`；
- 全文件 UTF-8、可 `json.load`。

### 2.5 评分器（Z 产出）

```bash
python -m eval.score --pred work/pred_val.json --split val --out work/reports/val.json
```

输出：`R@1/R@5/Acc@0.5/Acc@0.75/总分` + 按类别/按尺寸（<16px / 16–32 / 32–64 / >64）+ bootstrap 95% CI + 错例 CSV。
**唯一口径**：所有人口头说的分数必须来自这个脚本，禁止手算。

### 2.6 实验台账（Z 维护）

`experiments/<YYYYMMDD>_<owner>_<tag>/`

```
config.json      # 超参、数据 split、模型 revision
metrics.json     # 评分器输出
git_sha.txt      # 代码版本
env.txt          # pip freeze / conda list
time.txt         # 训练/推理用时
notes.md         # 一句话结论 + 是否进入下一轮
```

`reports/leaderboard.md` 只由 Z 更新，按"总分/Acc@0.5/R@5/用时/镜像大小"排序，并标注 dev4 还是 val。

## 3. 分支与协作规则

```
main                 # 只接受 PR，保持可交付
├── dev-m            # 定位
├── dev-s            # 检索/重排
└── dev-z            # 评测/交付
```

- 提交前缀：`[M]` / `[S]` / `[Z]`；一个 PR 只做一件事。
- 改接口（split/candidates/rerank/pred 格式）必须 @ 另外两人 review；不 review 不合。
- 不提交：数据、权重、`work/`、`experiments/` 大文件（已在 `.gitignore`）。
- 每天 21:30 前在群里发三行：**完成 / 下一步 / 阻塞**；超过 2 小时的阻塞直接 @M，超过 4 小时切备用方案，禁止静默硬啃。

## 5. 平台资源分配（自强5000 单卡 A100-40GB）

- 计费：**80 核时/卡时**；7000 核时 ≈ **87.5 卡时**。
- 预算：本项目 ≤ **35 卡时**（留 52 卡时余量）。

| 用途 | 预算 | 说明 |
|---|---:|---|
| 环境搭建（一次性） | 2h | micromamba + torch + 依赖；装到 `~/conda/envs/rsg` 持久盘 |
| YOLO 基线/对照 | 3h | 三组分辨率 + GDINO |
| 检测器全量训练 | 8h | YOLO11m + 切片；早停 |
| 重排训练 | 5h | CLIP 适配层，小模型 |
| 检索实验 | 4h | 特征预计算 + 融合调参 |
| 集成/计时/复现 | 5h | Docker 内测（若平台支持）|
| 缓冲 | 8h | 只用于门禁失败时补跑 |

**纪律**：
1. 开机前脚本已写好、数据已上传；开机只执行，不现场调试。
2. 每次容器 ≤2 小时；长任务用 `nohup`，断线不中断。
3. 结束前 `sync` → 打包 → 下载 → 校验 sha256 → **立即销毁**。
4. 任何"先开着卡想想"都是烧钱，禁止。
